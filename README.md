# Vision Modpack

Модпак, построенный на **пяти столпах**, которые должны работать как единая экосистема прогрессии и контента.

---

## 🎯 Общая концепция

| # | Столп | Роль в модпаке |
|---|---|---|
| 1 | **Магия** — Grimoire | Конструктор заклинаний, вертикаль «ремесленник ↔ воин» |
| 2 | **Техника** — Чертёж / Проектор / Фабрикатор | Автоматизация через математическое моделирование схем |
| 3 | **Дерево навыков** | Прогрессия, открывающая контент столпов 1–2 |
| 4 | **Данжи** | Источник ресурсов, редких глифов и блоков-апгрейдов |
| 5 | **Улучшенные ванильные механики** | Переосмысление базовых аспектов игры |

## 📖 Столп 1: Магия — Grimoire

Мод про **создание собственных заклинаний** через конструктор из глифов. Ориентирован как на «ремесленника» (сборка билдов, тюнинг), так и на «воина» (применение в бою).

### Гримуар и страницы

- **Гримуар** — предмет-конструктор заклинаний. Одна страница = одно заклинание.
- Количество **страниц** в гримуаре и **слотов** на странице — прокачивается.
- В будущем: **специализация** для каждой страницы и/или всего гримуара, дающая бонусы определённым типам глифов.
- **При смерти гримуар не выпадает.**
- За весь геймплей у игрока может быть **много гримуаров** (коллекция в Библиотеке), но **единовременно в инвентаре — только один** (геймплейное ограничение). Смена активного гримуара — только через **Библиотеку** (см. ниже), вне боя.

### Глифы: три уровня глубины

| Уровень | Категория | Правила |
|---|---|---|
| **1** | Форма / Стихия | Ровно одна форма (обязательна), ровно одна стихия. Дублирование запрещено. |
| **2** | Эффекты | От 0 до «сколько влезет», **без дублирования**. |
| **3** | Модификаторы / Модификаторы формы | Можно дублировать, занимают любые слоты. **Усиливают ближайший предшествующий якорный глиф** (форму, стихию или эффект), но **не другие модификаторы**. |

- **Форма** — способ наложения (снаряд, на себя, касание и т.д.).
- **Стихия** — элементальная принадлежность (огонь, лёд, вода...).
- **Эффекты** — статусы на цель/кастера (лечение, ускорение, замедление...).
- **Модификаторы** — усиливают элемент; **модификаторы формы** — меняют поведение формы (раздвоение, фокус, разброс...).

**Стек модификаторов:**
Цепочка `огонь → усиление → усиление` означает, что **оба** усиления баффают
**огонь**, а не «усиление усиливает усиление». Модификаторы — это множители
якоря, а не цепочка.

| Последовательность | Что происходит |
|---|---|
| `projectile → fire → bigger → bigger` | **Оба** `bigger` усиливают `fire`. |
| `projectile → fire → bigger → heal → bigger` | Первый `bigger` усиливает `fire`, второй — `heal`. |
| `projectile → fire → split → spread` | `split` и `spread` — модификаторы **формы**, применяются к `projectile`, а не к `fire`. |

### Обычные и развитые глифы

- **Обычные** — открываются в дереве навыков, покупаются за ресурсы из данжей.
- **Развитые**:
  - Встречаются только в узлах дерева навыков или как награда в данжах.
  - Часто сильнее, с нестандартными характеристиками.
  - Некоторые совмещают **форму и стихию одновременно** (например, `fireball`).
  - **Нельзя улучшать на верстаке глифов** (кнопки `+` и `-` блокируются).

### Верстак глифов

Блок-станция для тюнинга глифов очками характеристик.

- **Бюджет очков на характеристику** определяется уровнем этой характеристики в дереве навыков. **Точное число будет определено на этапе тестирования и балансировки готового проекта** — сейчас в коде стоит «без ограничения» (заглушка).
- Очки можно **перераспределять в любой момент**, но только на верстаке.
- Ограничение на количество очков в одну характеристику — **TBD** (появится вместе с балансом).

### Библиотека и смена гримуара

Библиотека — структура в отдельном измерении, куда игрок может **попасть в любой
момент вне боя** (снимается combat-lock). Здесь хранятся все гримуары игрока.

**Смена гримуара ничего не стоит и ничего не теряет:**
- Игрок кладёт текущий гримуар на полку и берёт любой другой из своей коллекции.
- Магическая прокачка **не теряется** — она привязана к гримуару и остаётся на полке.
- Экипировка и расходники сохраняются.
- Ограничение — только **время**: сходить в Библиотеку и вернуться занимает время,
  а в бою (combat-lock) переключение недоступно в принципе.

**Зачем это нужно:**
- Убирает горизонтальный гринд «прокачай всё» — каждый гримуар это отдельный
  архетип со своим деревом.
- **Реинкарнация по желанию**, а не по принуждению: игрок сам решает, когда
  сменить роль (атакующий маг → чарователь → фермер), и может вернуться к
  старому гримуару без потерь.
- **Не абузится**: единственная «стоимость» переключения — время и контекст
  (нельзя в данже, нельзя в бою). Будучи на базе, игрок сходит за шахтёрским
  гримуаром и покопает; будучи в бою с боссом — останется с тем, что есть.

**Можно ли держать всё в одном гримуаре?**
Технически — да, но гримуар всё равно специализирован (слоты, специализация
страниц, бюджет очков). На практике игрок либо держит минимум, либо меняет
гримуар под задачу. Маг огня не пойдёт рыбачить, а зельевар не отправится бить
босса в данже — это и есть задуманный геймплей.

**Дополнительно в Библиотеке:**
- **Арена для PvP** без потерь.
- **Начальные данжи** для новичков.
- _В планах:_ демонстрация билдов, новые полки за ресурсы из данжей или
  достижения в дереве навыков.

### Планы по интеграции с ванилью

- Взаимодействие магии с **зачарованием**, **крафтом вооружения**, **зельеварением**.
- Улучшение переплавки, рыбалки, добычи ресурсов и фермерства через способы и эффекты магического мода.

## ⚙️ Столп 2: Технический мод

Базируется на стандартном наборе машин (**дробитель, компрессор, экстрактор** и т.д.), но **спроектирован под математическое моделирование**. Главная фишка — связка **Чертёж → Проектор → Фабрикатор**.

### Проектор

- Помещаешь **пустой чертёж** — проектор сканирует область вокруг и записывает её в память, преобразуя в **схематику + математическую модель**.
- Два режима:
  - **Копирование** — схема сохраняется, оригинал остаётся.
  - **Поглощение** — схема считается завершённой, всё в области действия **пропадает** при извлечении чертежа.

### Чертёж: 4 области данных

1. **Принимаемые ресурсы** — что можно подавать в интерфейс механизма у зелёной зоны импорта.
2. **Потребляемая энергия**.
3. **Количество тиков** на всю операцию.
4. **Выходящий ресурс**.

> ⚠️ Техническая сторона ещё не до конца проработана — возможно, пункты 1 и 4 окажутся не нужны.

### Применение чертежа

- **Проектор** с завершённым чертежом — восстанавливает сохранённую схему в области проектора.
- **Фабрикатор** с завершённым чертежом — работает согласно **математической модели** внутри чертежа (по сути, «исполняет» схему как производственный процесс).

### Блоки-апгрейды

Размещаются рядом с машинами и модифицируют их работу:
- **Скорость** ↑
- **Потребление** ↓
- **Мультипликатор** работы ↑

Находятся как награды в данжах.

### Используемые API и подходы

- **Data Components** (`DataComponents.CUSTOM_DATA`) — хранение состояния гримуара в NBT.
- **CustomPacketPayload + StreamCodec** — сетевой протокол (`GrimoireActionPacket`, `AllocatePointPacket`).
- **DeferredRegister** — регистрация предметов, блоков, сущностей, эффектов, меню.
- **IMenuTypeExtension** — меню верстака глифов с передачей `Inventory`.
- **SynchedEntityData** — синхронизация `SpellProjectile`.
- **EventBusSubscriber** — модульная регистрация клиентских и серверных событий.
- **Кастомные GUI** — `GrimoireScreen` (книга с TOC, букмарками, drag-n-drop), `GlyphWorkbenchScreen` (тюнинг глифов).
- **Система статов** — `Stat` (enum), `StatMod` (`BASE/ADD/MULT`), `StatBlock`, `GlyphBalance`.
- **Парсер заклинаний** — `SpellParser` + `SpellAggregator` + `SpellDescriber`.
- **Локализация** — `en_us.json` и `ru_ru.json` (все строки переведены в код через `Component.translatable`).

## 🐞 Известные баги

- **Дублирование гримуара при выдаче через `/give`:** Команда `/give grimoiremod:creative_grimoire` выдаёт 2 гримуара и пишет в чат `[Воздух]`. 
  *Причина:* Ванильная команда `/give` вызывает `ItemTossEvent` *до* того, как устанавливает `target` на сущность дропа. Из-за этого перехватчик дропа (возвращающий гримуар в инвентарь) срабатывает на фейковый дроп команды, добавляя второй экземпляр.
  *Решение (временное):* Использовать `/grimoiredel` для очистки лишнего. Влияет только на креатив/команды, не на обычный геймплей. Фикс отложен, так как требует глубокого перехвата логики команд или отказа от защиты дропа.

## 🎨 Временные эстетические ограничения

- **Разное число слотов на странице между экранами.** `GrimoireScreen` показывает **7** слотов на странице, `GlyphWorkbenchScreen` — **10**. Это **осознанное временное решение**, а не баг:
  - В книге-гримуаре 7 слотов колонкой смотрятся эстетичнее и оставляют место для блока «Итог».
  - В верстаке глифов сетка **5×2** из 10 слотов гармоничнее заполняет прямоугольную область тюнинга.
  - **7 — это временный максимум для страницы заклинания**, продиктованный компоновкой.
  - Увеличение лимита слотов на странице — задача **геймплейная** (балансировка сложности заклинаний и глубины прокачки страниц), а не архитектурная: `MAX_SLOTS_PER_PAGE` уже вынесен в константу, `GlyphPage.slotCount` хранится в NBT, оба экрана рисуются циклами по этому значению. Привести к единому значению можно в любой момент, без переработки структур данных.
  - **Статус:** отложено до этапа балансировки.

## 💻 Шпаргалка команд

### 🖥️ Git Bash (Терминал)

Все скрипты запускаются из корня проекта.

| Команда | Что делает |
|---|---|
| `./apply_update.sh` | **Главная команда.** Применяет патч из `apply_update_body.sh`, компилирует, делает дамп и запускает игру. |
| `./gradlew compileJava` | Только компиляция (без запуска игры). |
| `./gradlew runClient` | Запуск клиента Minecraft с модом. |
| `./gradlew runServer` | Запуск выделенного сервера. |
| `./dump_project.sh` | Собирает весь код и структуру проекта в `project_dump.txt`. |
| `SKIP_COMPILE=1 ./apply_update.sh` | Применить патч, но **не** компилировать. |
| `SKIP_RUN=1 ./apply_update.sh` | Применить патч и скомпилировать, но **не** запускать игру. |
| `SKIP_DUMP=1 ./apply_update.sh` | Применить патч и запустить, но **не** делать дамп. |

### 🎮 Внутриигровые команды (Чат)

| Команда | Что делает |
|---|---|
| `/glyphtest <glyph_id> <points>` | Выдаёт гримуар с указанным глифом в первом слоте. Пример: `/glyphtest fireball 5`. |
| `/grimoiredel` | Удаляет текущий гримуар из инвентаря (для чистого теста). **Требует OP (permission 2).** |
| `/give @s grimoiremod:grimoire` | Ванильный способ получить пустой гримуар. |
| `/give @s grimoiremod:glyph_workbench` | Получить верстак глифов. |
| `/kill @s` | Проверить, что гримуар не выпадает при смерти. |
| `/gamemode creative` | Переключиться в креатив (если нужно). |

## 🛠️ Инструменты разработчика

> ⚠️ Этот раздел не относится к геймплею. Это внутренний workflow для сборки и итераций над кодом.

Все изменяемые файлы перед патчем автоматически бэкапятся в папку `.patch_backup_<timestamp>/`.

- **`dump_project.sh`** — собирает структуру файлов и весь исходный код в один текстовый файл `project_dump.txt`. Удобно для передачи контекста ИИ-ассистентам или для быстрого поиска по всему проекту.
  ~~~bash
  ./dump_project.sh                    # всё в project_dump.txt
  ./dump_project.sh out.txt java       # только структура + Java
  ./dump_project.sh out.txt config     # только gradle + toml + json
  ~~~

- **`apply_update.sh`** — скрипт-обёртка для быстрого применения патчей. Запускает тело обновления (`apply_update_body.sh`), затем автоматически компилирует проект, делает дамп и запускает клиент.
